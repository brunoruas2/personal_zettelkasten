# Zettelkasten

**[English](#english) · [Português](#português)**

---

## English

An offline-first PWA for interlinked notes, backed by your own Go server. Runs in the
browser as an installable app (iOS, Android, desktop) and keeps working with no
connection — every note lives in IndexedDB and syncs back when the network returns.

Built to be **self-hosted**: one script brings the whole thing up on `localhost`. No
third-party service, no cloud account, no telemetry.

### Running locally

**Requirements:** Node 20+, [pnpm](https://pnpm.io/installation), Go 1.26+

```bash
git clone <repo-url> zettelkasten
cd zettelkasten
./setup.sh     # installs deps, generates JWT_SECRET, builds everything, creates the admin
./start.sh     # starts API (:3001) + web (:3000)
```

Open <http://localhost:3000> and sign in with the user you created during `setup.sh`.

`setup.sh` is idempotent — run it again after a `git pull` to rebuild. An existing
`apps/api/.env` is never overwritten.

Both scripts are bash: they run on Linux, macOS, WSL and Git Bash on Windows.

On a low-memory machine, cap the Node heap during the build:

```bash
NODE_HEAP=384 ./setup.sh
```

#### Adding more users

Sign-up is **invite-only** — there is no open registration page. An admin mints an invite
(valid for 7 days), which is then redeemed against the register endpoint:

```bash
# 1. as an admin, create an invite
curl -X POST http://localhost:3000/api/admin/invites \
  -H "Authorization: Bearer $TOKEN"

# 2. redeem it
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"invite_token":"<token>","username":"alice","password":"<password>"}'
```

Or skip invites entirely and create the user straight from the terminal:

```bash
cd apps/api
go run ./cmd/createuser/main.go -username <name> -password <password> -role member
```

### Features

- Markdown notes with **wiki links** (`[[note title]]`) and inline autocomplete
- **Galaxy map** — interactive graph of your connections (Canvas 2D + d3-force), with focus
  mode, per-cluster colors and editing a note straight from the map
- **Offline-first** — notes live in IndexedDB and the service worker pre-caches every route,
  so the whole vault is available with no network
- Automatic sync with the backend (timestamp delta, server wins conflicts)
- Passkeys (WebAuthn) alongside password login
- WYSIWYG editor (TipTap) with a mobile formatting toolbar and `/` commands
- Special blocks: PlantUML, chord sheets with transposition, ABC sheet music, syntax-
  highlighted code, tables and task lists
- JSON and Markdown (`.zip`) export, PDF export, bulk import — see [IMPORT_FORMAT.md](IMPORT_FORMAT.md)
- **Backup key** — a key-authenticated URL for scheduled cron backups
- Tags, full-text search (FTS5), backlinks, orphan filter, per-user default template
- Multi-user, invite-based

### Stack

| Layer | Technology |
|---|---|
| Frontend | Next.js 15 App Router, Tailwind CSS, Zustand, Dexie (IndexedDB) |
| Editor | TipTap 3 + tiptap-markdown |
| PWA / Offline | `@ducanh2912/next-pwa` + Workbox + a custom service worker |
| Backend | Go, chi, SQLite (`modernc.org/sqlite`, CGO-free) |
| Auth | JWT (15 min) + HttpOnly refresh token (30 days) + WebAuthn/passkeys |
| Diagrams | `@plantuml/core` compiled to WASM — rendered in the browser, no Java |

Everything that renders (PlantUML, chords, sheet music, syntax highlighting) runs **on the
client**. The backend only stores and syncs text.

### Monorepo layout

```
apps/
  web/        — Next.js (frontend)
  api/        — Go REST API
packages/
  core/       — business logic in pure TypeScript (no browser deps)
  db-web/     — Dexie implementation of ZettelRepository
```

### Configuration

#### Backend — `apps/api/.env`

Created automatically by `setup.sh` from `.env.example`, with a random 256-bit
`JWT_SECRET`.

```env
PORT=3001
DB_PATH=zettelkasten.db
JWT_SECRET=<generated by setup.sh — replace it if you expose this to the internet>
ALLOWED_ORIGIN=http://localhost:3000
WEBAUTHN_RP_ID=localhost
WEBAUTHN_RP_NAME=Zettelkasten
WEBAUTHN_RP_ORIGIN=http://localhost:3000
```

When you publish under a domain, point `ALLOWED_ORIGIN` and the three `WEBAUTHN_*` vars at
the real domain — passkeys are bound to their origin and stop working if these drift.

#### Frontend — `apps/web/.env.local` (optional)

Only needed if the API is not at `http://localhost:3001`:

```env
API_URL=http://localhost:3001
```

No `NEXT_PUBLIC_` prefix: the variable is used only by the Next.js server-side proxy and
never reaches the browser. The browser always talks to the same origin, so CORS never
enters the picture.

### Development

```bash
# Frontend in dev mode (hot reload; the service worker is disabled)
pnpm --filter @zettelkasten/web dev

# Backend in dev mode
cd apps/api && go run ./main.go

# Type-check every package
pnpm type-check

# Unit tests (packages/core)
pnpm --filter @zettelkasten/core test

# Offline/PWA E2E tests (require a production build)
pnpm --filter @zettelkasten/web test:e2e:build
```

The production build skips type-check and lint on purpose (`next.config.ts`) so it fits on
small machines — run `pnpm type-check` separately before shipping.

### Server deployment

To expose it on the internet, the tested path is Nginx → PM2 → Next.js (:3000) + Go API
(:3001):

1. `nginx.conf.example` — TLS reverse proxy, routing `/api/` to the backend
2. `ecosystem.config.js` — PM2 configuration for both processes
3. `deploy.sh` — `git pull` → `pnpm install` → build → `pm2 restart`

```bash
# on the server, inside the repo folder
./deploy.sh
```

Set your domain in `nginx.conf.example` and in the `WEBAUTHN_*` vars before the first
deploy.

### Automated backup

Under Settings → **Backup key**, generate a 256-bit key (shown exactly once). Then:

```bash
cp scripts/.env.example scripts/.env   # fill in ZETTEL_BACKUP_URL and ZETTEL_BACKUP_KEY
python scripts/backup.py               # run once
python scripts/backup.py --loop 60     # every 60 minutes
```

Or straight from cron:

```bash
0 3 * * * curl -s "https://your-domain.com/api/backup/export?key=<key>" \
  -o "/backups/zettelkasten-$(date +\%Y-\%m-\%d).json"
```

> `/api/backup/export` requires no login — **the key is the only authentication factor**.
> Treat the URL like a password. To invalidate it, revoke the key under Settings.

### Import

`POST /api/import/json` accepts the same envelope the export produces. The full schema,
with conversion guides from Obsidian, Notion, Roam and Logseq, is in
[IMPORT_FORMAT.md](IMPORT_FORMAT.md).

## Português

PWA offline-first para notas interligadas, com backend próprio em Go. Roda no browser como
app instalável (iOS, Android, desktop) e continua funcionando sem internet — todas as notas
ficam no IndexedDB e sincronizam quando a rede volta.

Feito para ser **auto-hospedado**: um script sobe tudo em `localhost`, sem serviço externo,
sem conta em nuvem, sem telemetria.

### Rodando local

**Pré-requisitos:** Node 20+, [pnpm](https://pnpm.io/installation), Go 1.26+

```bash
git clone <url-do-repo> zettelkasten
cd zettelkasten
./setup.sh     # instala deps, gera JWT_SECRET, compila tudo, cria o admin
./start.sh     # sobe API (:3001) + web (:3000)
```

Abra <http://localhost:3000> e entre com o usuário criado no `setup.sh`.

`setup.sh` é idempotente — pode rodar de novo depois de um `git pull` para recompilar. Um
`apps/api/.env` já existente nunca é sobrescrito.

Os scripts são bash: rodam em Linux, macOS, WSL e Git Bash no Windows.

Em máquina com pouca RAM, limite o heap do Node no build:

```bash
NODE_HEAP=384 ./setup.sh
```

#### Criar mais usuários

O cadastro é **invite-only** — não existe tela de registro aberta. Um admin gera um convite
(válido por 7 dias), que depois é resgatado na rota de registro:

```bash
# 1. como admin, criar o convite
curl -X POST http://localhost:3000/api/admin/invites \
  -H "Authorization: Bearer $TOKEN"

# 2. resgatar
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"invite_token":"<token>","username":"alice","password":"<senha>"}'
```

Ou pular o convite e criar o usuário direto pelo terminal:

```bash
cd apps/api
go run ./cmd/createuser/main.go -username <nome> -password <senha> -role member
```

### Funcionalidades

- Notas em Markdown com **wiki links** (`[[título da nota]]`) e autocomplete inline
- **Mapa galáxia** — grafo interativo das conexões (Canvas 2D + d3-force), com modo foco,
  cores por cluster e edição de nota direto no mapa
- **Offline-first** — as notas vivem no IndexedDB; o service worker pré-cacheia todas as
  rotas, então o cofre inteiro fica disponível sem rede
- Sync automático com o backend (delta por timestamp, servidor vence conflitos)
- Passkeys (WebAuthn) além de login por senha
- Editor WYSIWYG (TipTap) com barra de formatação para mobile e comandos por `/`
- Blocos especiais: PlantUML, cifras com transposição, partituras ABC, código com destaque
  de sintaxe, tabelas e listas de tarefas
- Export JSON e Markdown (`.zip`), export em PDF, import em lote — ver [IMPORT_FORMAT.md](IMPORT_FORMAT.md)
- **Chave de backup** — URL autenticada por chave, para backup agendado por cron
- Tags, busca full-text (FTS5), backlinks, filtro de órfãs, template padrão por usuário
- Multi-usuário com convites

### Configuração

#### Backend — `apps/api/.env`

Criado automaticamente pelo `setup.sh` a partir de `.env.example`, com um `JWT_SECRET`
aleatório de 256 bits.

```env
PORT=3001
DB_PATH=zettelkasten.db
JWT_SECRET=<gerado pelo setup.sh — troque se for expor na internet>
ALLOWED_ORIGIN=http://localhost:3000
WEBAUTHN_RP_ID=localhost
WEBAUTHN_RP_NAME=Zettelkasten
WEBAUTHN_RP_ORIGIN=http://localhost:3000
```

Ao publicar num domínio, ajuste `ALLOWED_ORIGIN` e as três vars `WEBAUTHN_*` para o domínio
real — passkeys são atreladas à origem e param de funcionar se isso divergir.

#### Frontend — `apps/web/.env.local` (opcional)

Só é necessário se a API não estiver em `http://localhost:3001`:

```env
API_URL=http://localhost:3001
```

Sem prefixo `NEXT_PUBLIC_`: a variável é usada apenas pelo proxy do servidor Next.js, nunca
chega ao browser. O browser sempre fala com a mesma origem, então não há CORS no caminho.

### Backup automático

Em Configurações → **Chave de backup**, gere uma chave de 256 bits (exibida uma única vez).
Depois:

```bash

python scripts/backup.py               # uma vez
python scripts/backup.py --loop 60     # a cada 60 minutos
```

Ou direto no cron:

```bash
0 3 * * * curl -s "https://seu-dominio.com/api/backup/export?key=<chave>" \
  -o "/backups/zettelkasten-$(date +\%Y-\%m-\%d).json"
```

> O endpoint `/api/backup/export` não exige login — **a chave é o único fator de
> autenticação**. Trate a URL como uma senha. Para invalidar, revogue a chave em
> Configurações.
